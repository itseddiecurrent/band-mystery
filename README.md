# 《乐队酒局杀人事件》

一款受《Raging Loop》启发的单人 2D 浏览器互动推理小说。你扮演乐队的调音师，在一场演出后的庆功宴上卷入一桩命案。

## 场景、对话与调查

- 以全屏场景插画、角色立绘、旁白和对话推进剧情。不同地点、视角和剧情节点可以切换画面。玩家主动交谈或通过调查、剧情事件触发对话时，显示当前说话者的头像，台词出现在画面底部。对话期间只模糊背景场景，头像和台词保持清晰；对话结束后恢复清晰的场景。按 Enter 或点击对话框推进对话、旁白和回放。
- 调查时，玩家可打开**放大镜**，在场景图上移动或拖动镜头，查看局部细节。放大画面时可以直接点击已配置的线索热点，查看特写、显示洛克的观察或触发对话。发现的线索会记录到线索册，可随时回看。
- 用点击选择线索、比对照片和实物、提交推理。根据举证结果推进案情还原与指认。
- **后退 / 前进**：后退恢复上一步的剧情与线索状态，前进推进对白或重走刚退回的步骤。玩家可以先去相邻地点察看，相关剧情在调查条件满足后触发。

## 技术栈与实现

首版使用 HTML、CSS 和原生 JavaScript（ES 模块），无需前端框架、游戏引擎或后端。HTML 提供游戏界面，CSS 负责排版、对话框和放大镜效果，JavaScript 管理剧情、调查和存档。

- **场景与对话**：将背景图、立绘、台词、选项和场景跳转写在 JavaScript 数据模块中，与推进剧情的代码分开。新增场景主要靠补充数据和插画。
- **放大镜与调查**：用相对于场景图片的百分比定义可点击区域，让热点随图片一起缩放。放大镜通过 CSS 显示局部放大的画面，关键线索可打开独立的高清特写。
- **线索与举证**：每条线索使用固定 ID。游戏用这些 ID 记录已发现的线索，检查玩家提交的证据，并解锁下一段剧情。进度保存在 `sessionStorage`。

当前已贯通到凯特与小柔谈话后的最终沉默。后半段先以四组报告复查、嫌疑人指认和连续对白承载；完整选证与三轮举证交互待完善。托尼备用枕头回忆图已生成并接入，坠楼回忆图已确认并接入，蛋仔用枕头杀人的回忆图也已确认并接入，详见《场景.txt》和 `src/content.mjs` 的 `pendingArtwork`。

## 网页版发布

网页版是主要发行方式。玩家打开链接即可游玩，无需安装或手动下载整包。游戏可部署到 GitHub Pages 等静态托管服务，由浏览器运行 HTML、CSS 和 JavaScript。

开发时保留 `assets/` 中的原图。场景插画发布为优化后的 JPEG，角色立绘使用独立的 WebP 文件；运行 `sh scripts/optimize-scenes.sh` 可重新生成场景 JPEG。游戏显示当前场景时会在后台预载下一句或相邻地点的图片。用于放大镜调查的图像保留原始尺寸，高清线索特写按需载入。

## 玩家进度与存档

首版无需账号或后端。每个标签页的游玩会话使用浏览器的 `sessionStorage` 自动保存当前进度和完整游玩记录。推进对话、进入新场景、发现线索、做出选择或提交举证后更新存档。

- **继续游戏**恢复本次会话最近的进度和记录，刷新同一标签页后仍可继续。
- **游玩记录**按时间归档已发生的剧情进度，包括场景切换、每句对话、调查发现、选择和举证。玩家可回看完整记录，也可从任何一段已触发的对话重新开始游玩。
- **从此处继续**恢复所选对话开始时的场景、线索、选择和剧情状态，后续获得的线索不会提前带入。原先走过的剧情仍可在记录中回看。
- **新游戏**在覆盖已有存档前提示确认。
- **退出游戏**清除本次会话的进度和记录。关闭游戏标签页也结束本次会话；重新打开链接开始新游戏。

## 可选离线版

网页版与离线版共用游戏代码和素材。离线版可将优化后的图像、JavaScript 和 CSS 嵌入单个 `index.html`，供玩家下载后离线打开。发布前在断网环境下验证场景切换、对话、放大镜调查、线索回看和举证流程。

## 运行试玩

在项目目录运行 `python3 -m http.server 8000 --bind 127.0.0.1`，然后用浏览器访问 `http://127.0.0.1:8000/`。当前试玩从沙发醒来到进入医院病房为止，途中可以比对领带夹和合照，也可以选看去年夏天的合照。打开「记录」可从已触发的对话重新开始，刷新同一标签页可继续本次进度。

运行 `node --test` 检查调查推进条件、线索登记、屏蔽器和报警状态、存档恢复、回溯和素材引用。

### 剧情画布

```sh
node scripts/story-editor.mjs
```

画布采用从左到右的树状节点与网格背景，初始包含当前主线的 27 个节点。单击选择、双击查看详情，可在任意节点添加子节点、同级或分支，并编写进入条件和剧情笔记。支持大纲搜索、折叠、平移缩放、调整新节点的连接、撤销和重做。

- **灰色：原有剧情，只读。** 可以查看或附加新分支，不能修改原文、删除或移动原有节点。
- **黄色：新增，尚未实现。** 新节点默认使用此状态，可以自由编辑。
- **绿色：新增，已实现。** 在详情中手动标记，表示对应游戏实现已另行完成；标记本身不会修改或检查游戏代码。

修改自动保存到 [docs/story-tree.json](docs/story-tree.json)，也可手动保存或导出 JSON 备份。导入支持撤销，但必须保留原有只读剧情；同时打开多个窗口时，版本检查会阻止旧窗口覆盖新修改。

画布是独立创作文档，**编辑节点不会改变当前可玩的游戏**。将新分支接入游戏仍需单独修改剧本、剧情数据与逻辑，并验证相关路线。启动画布不需要数据库或凭据。详见[使用说明](docs/story-editor.md)与[界面预览](docs/story-editor-preview.jpg)。

### 游戏内剧情路线

游戏右上角的 **剧情路线 / Storyline** 打开全屏横向路线图：以聚会房屋为暗色背景，用场景缩略图和细线连接剧情，顶部六段章节导航，底部提供探索进度、缩放与当前位置。目前实装只有一条主线，共 26 个剧情节点；调查顺序与四项复查的顺序不构成分支。已探索节点显示标题与画面，当前位置以菱形和文字标记，未探索节点呈灰色且只显示 `???`，不加载对应缩略图。庆功宴节点记录已探索的汽水选项，并区分本次选择与此前看过的选项。调查记录收在节点下方的展开项中，不另画成剧情分支。

地图随当前标签页存档恢复，回退后仍保留本次存档看过的内容；开始新游戏会重新隐藏未探索内容。有真实历史检查点的节点可选择“从此处继续”，沿用游戏现有回退功能。地图提供定位、滚动和缩放，中英文均可用。它只包含已实装剧情，与创作画布中的待实现分支分开。

可拖动、触屏滑动或滚轮横向浏览；选中节点后可用方向键移动，Esc 返回游戏。原生模态窗口限制焦点范围，关闭后返回游戏工具。手柄支持左右方向 / 摇杆切换已探索节点、肩键切换章节、A 返回所选检查点、B 关闭；实体手柄仍需人工试玩。

参见[桌面预览](docs/storyline-preview.jpg)、[超宽屏](docs/storyline-ultrawide-preview.jpg)、[竖屏](docs/storyline-portrait-preview.jpg)与[手机预览](docs/storyline-phone-preview.jpg)。

### 游玩统计看板

```sh
node scripts/analytics-dashboard.mjs
```

看板按时间范围和游戏版本查看匿名开局数、估算玩家数、完成率、结局分布、节点到达情况、活跃时长、调查选择及未完成游玩的最后停留位置，帮助判断玩家在哪些地方停下或遇到困难。数据是匿名遥测的汇总，活跃时长与玩家数均为估算。

运行前需按[统计说明](analytics/README.md)在本地 `.env` 配置 `ANALYTICS_DASHBOARD_TOKEN`，并能访问已配置的统计服务。令牌由本地服务使用，不传给看板浏览器，不随游戏发布；不要提交 `.env` 或把令牌写进前端。

看板查看已有试玩统计，与剧情画布的数据及游戏存档分别管理。查看看板不会应用剧情分支；详情、统计口径与配置见 [analytics/README.md](analytics/README.md)。

## GitHub Pages 自动部署

推送到 `main` 后，`.github/workflows/deploy-pages.yml` 先运行测试，再发布 `index.html`、`src/` 与 PNG 素材；剧本文档和生成提示词不放入部署产物。仓库 Pages 的发布方式设为 GitHub Actions。

进入游戏前需要输入硬编码邀请码。验证结果保存在当前标签页的 `sessionStorage`，刷新无需重复输入。此入口仅用于便捷邀请，不提供服务端身份验证；公开仓库与客户端源码中可以读取邀请码。

## 立绘加载

角色立绘使用 `assets/portraits/` 内的 WebP，保留原 PNG 作为制作源图。标题页预加载并解码全部九张立绘，发言切换时复用已解码的图片节点。更新立绘后运行 `sh scripts/optimize-portraits.sh` 重新生成（需要 `cwebp`），一并提交 WebP 文件。
