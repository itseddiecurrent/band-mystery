# 游戏中英文支持

标题页的语言下拉框位于“开始游戏 / New Game”之前，可选择简体中文或 English。默认中文，选择保存在浏览器 `localStorage`，与存档、邀请码验证和匿名统计分别管理。刷新后可选择另一种语言，再点击“继续游戏”，不会改变已有进度和线索。

## 翻译范围与名字

UI、对话、旁白、线索说明、调查热点、场景名称、人物档案、通知、确认框、记录和辅助功能标签均通过统一翻译层展示。现有插画和证据图片保持原样，英文说明显示在相应线索面板；图片中原有的中文并未重绘。

## 新增或修改剧情

**游戏文本的每次改动，都必须在同一提交中提供中英文。**

1. 在 `src/content.mjs` 中修改中文对话、线索、场景或人物文本。
2. 在 `src/locales/en.mjs` 中新增或更新对应条目。键是完整中文原文，值是英文译文；中文原文改变时，英文条目的键也要更新。
3. 通过 `t()` 或已有翻译助手显示文本。角色逻辑、证据 ID、素材文件名、存档中的原始记录不改为英文。
4. 执行 `node --test`。新增文本缺少英文、英文仍含中文、占位符不一致、角色英文拼写不符时，测试失败。PR 自动检查和发布前测试都会运行这些检查。
5. 实际用中英文查看受影响场景，检查长英文的换行、按钮、窄屏与旧进度恢复。

例如，新增中文线索说明时，同时补充英文：

```js
// src/content.mjs
label: '一封未寄出的信'

// src/locales/en.mjs
'一封未寄出的信': 'An unsent letter'
```

新增静态 UI 使用 `data-i18n="中文原文"`；辅助功能名称使用 `data-i18n-aria-label`。动态 UI 使用命名占位符：

```js
t('去{place}', { place: scenes[destination].label })
```

英文条目保留相同的 `{place}`，必要时可调整顺序。不要用英文显示名调用角色逻辑，也不要把多种语言的字符串片段拼成一句话。

## 英文叙事与人物声音

对话和旁白按完整场景翻译与复读，避免逐句直译造成的机械感。当前英文使用 `translate-visual-novel` 从中文重新翻译，并经过独立代理逐条审核。后续翻译参考[翻译简报](translation-brief.md)：保留人物语气、关键证物、未确定的说法与沉默；检查来源忠实度，再检查英文节奏。技术报告仍需准确。格式检查通过仅说明条目完整，不代表文学质量已经得到审核。

## 兼容性与边界

- 语言层只改变显示；中文剧情和英文剧情共享同一套调查条件、回溯和存档。
- 当前及旧版存档的中文记录在展示时翻译。极旧存档中已不再存在的文本保留原文，避免无法继续游玩。
- 浏览器禁止保存语言偏好时仍能切换语言；下一次打开时可能恢复默认中文。
- 本次为可玩的游戏提供中英文。剧情画布和统计看板属于独立创作工具，界面语言不在本次范围内。
- 添加带重要文字的新证据图片时，同时提供两种语言可读的文字说明或本地化素材，不能只依赖图片里的一种语言。
